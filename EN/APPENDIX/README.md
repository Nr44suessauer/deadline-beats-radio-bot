### Capture in the Interface (tested)

The capture program controls the open n8n page. Six rules, without which the
images will be incorrect (all measured on 2026-09-22):

1. **Force lighting** — `page.emulateMedia({ colorScheme: 'light' })`. n8n follows the
   system setting; without this, the dark area appears, where the frame colors and
   the white cards are barely visible.
2. **Hide UI elements**, otherwise "Execute workflow" buttons appear in each tile,
   the node buttons in the top right, and the tab "Pill" in the header:
   `[data-test-id="canvas-controls"], [data-test-id="canvas-minimap"],
   [class*="executionButtons"], [data-test-id="canvas-node-toolbar"],
   [data-test-id="canvas-handle-plus-wrapper"], [class*="_nodeButtonsWrapper"]
   { display: none !important; }`
   `[class*="tab-bar-container"], [class*="_main-header"] { visibility: hidden !important; }`
   (visibility instead of display — the header otherwise determines the layout.)
   Then move the **mouse out of the area** (e.g., on `5,800`), otherwise node toolbars appear.
3. **Measure the capture area, do not guess**: `[data-test-id="canvas"]` with
   `getBoundingClientRect()` — as of 2026-09-24: **1380×807.8 px (200.65)**, window
   1580×906. The size changes if the browser window is opened differently — then
   `KLIP`/`FENSTER` in `module-images-plan.py` follow.
4. **Set the zoom** with `zoom-in-button`/`zoom-out-button` (each click ×1.2 or ÷1.2). There is **no reset to default**: each run starts after loading on its own fit value (measured → `images/startscales.json`).
   Therefore, exactly `Startwert · 1,2^k` is reachable — `module-images-scales.py`
   calculates these values into the plan and writes a capture sheet for each run;
   it also adds **safety margins** (notes can be drawn below their frame).
   **Do not leave `zoom-to-fit`** — the button does not always work.
5. **Move** with a fake `WheelEvent` on `.vue-flow__pane`:
   measured is `Δtx = −0,5 · deltaX`. So `deltaX = −2 · Δx`. Recalculate for each tile,
   until the remaining offset is 0 (usually 2–3 events).
6. **Wait until the area stabilizes.** The zoom is in
   `style="transform: translate(…px,…px) scale(…)"` (large values in
   scientific notation — read numbers with `-?[\d.]+(?:e[+-]?\d+)?`). Before the
   capture, wait twice at intervals of 120 ms for the same value, then another ~0.7 s, otherwise the ongoing movement shifts the tile by a few pixels.

Tile name: `<bild>__t<nr>__x<tx>__y<ty>__s<scale>.png` (tx/ty/scale from the
capture, rounded to whole pixels; the scale with 5 digits).

### GIF Captures (as of 2026-09-22)

The two GIFs at the top of this document are generated from a **real test run** of the bot.
Two programs are sufficient, both without external packages:

| Tool | Task |

| --- | --- |

| `tools/gif-capture.js` | controls its own Brave window via the browser protocol, sets scale and view, initiates the test run, and captures the screen stream |

| `tools/gif-build.py` | calculates the image sequence to GIF (common color table, original time, synchronized cropping) |

Full image (the entire bot in motion):

```bash
cd ../..
node tools/gif-capture.js aufnehmen --ablauf RadioAgentBot \
  --ziel /tmp/gif-lauf/gesamt --dauer 26 --vorlauf 6 --befehl "spiele nirvana lithium"
python3 tools/gif-build.py /tmp/gif-lauf/gesamt \
  ../../Ai_Radio_Moderator_Bot/APPENDIX/images/bot-lauf-gesamt.gif \
  --abschnitte "6,6:15,6" --zeitgleich --luecke-max 250 --breite 1000 --farben 48 \
  --inhalt --inhalt-rand 2 --rahmen 1
```

`--inhalt` cuts **tightly around the node rectangles** (the boundary is measured in the
browser at all `.vue-flow__node` and recorded in the report), `--inhalt-rand 2` leaves
2% padding, `--rahmen 1` draws a fine gray line — otherwise the light
n8n area would blend with a white background.

Camera panning (the same run on a larger drawing area; the view is set in post-processing):

```bash
node tools/gif-capture.js aufnehmen --ablauf RadioAgentBot \
  --ziel /tmp/gif-lauf/gross --fenster 3200x2200 --massstab 0.36 --dauer 24 \
  --vorlauf 6 --befehl "spiele nirvana lithium"
python3 tools/gif-build.py /tmp/gif-lauf/gross \
  ../../Ai_Radio_Moderator_Bot/APPENDIX/images/bot-lauf-kamera.gif \
  --abschnitte "6,4:15,1" --mitlaufen 12 --fenster 1300x740 --breite 860 --farben 40 \
  --zeitgleich --luecke-max 250 --rahmen 1
```

`--mitlaufen` does not need a time plan: for each image, the area that has changed from the
previous image is determined (threshold 12), smoothed over 0.6 seconds, and cropped
out as a frame. The camera catches the run automatically — and stays at the spot where
something is happening.

**What was measured on 2026-09-22** (seven points, without which it wouldn't work):

1. **Only one run from the surface is drawn.** If the test input is triggered via the
   production address `/webhook/YOUR-WEBHOOK-PATH`, the image **does not change at all** — 328 images, all bit-identical. Correctly: click on `execute-workflow-button-Test-Eingang` in the
   editor and then
   `POST /webhook-test/YOUR-WEBHOOK-PATH?schluessel=…` send.
2. **The entire run lasts only about 5 seconds.** Individual images via
   `Page.captureScreenshot` take about 140 ms (roughly 7 images per second) — too coarse.
   Therefore `Page.startScreencast` (JPEG): it redraws at each redraw, measured
   40 to 240 ms apart.
3. **The image stream delivers the entire page**, not the drawing area. The cropping
   comes from `masse` in `aufnahme.json` (area from 200.65 in 2400×1400).
4. **Scale and view**: The mouse wheel **only moves** (factor −0.5 per unit),
   Ctrl does nothing, the scale changes **only via the buttons** (×1.2 per click).
   More precise than half a button step is not possible — otherwise the regulation would oscillate.
   The movement is on `.vue-flow__transformationpane` (not on
   `.vue-flow__viewport`), at the numerical value of the `matrix(…)`.
5. **The buttons are hidden after setting**: Whoever hides first clicks into empty space (flawless still image effect: all 328 images identical).
6. **The most beautiful image comes last**: n8n draws the green edges of the result only after about 15 seconds — before that, only the nodes light up.
7. **Login**: The capture profile `~/gif-aufnahme-profil-brave` contains a copy
   of the n8n cookies from the user's own Brave profile. It is therefore treated as an access value (readable only by the user). Whoever deletes it must log in manually (`node tools/gif-capture.js anmelden`).

Both GIFs are deliberately kept under 5 MB (target size for documentation);
knobs are `--breite`, `--farben`, and `--jedes`.

**Version for a post** (website, blog, chat): 800 points wide, without frame,
with labeling in the image. The bar sits at the top, is 30 points high, and is set in
DejaVu Sans Bold:

```bash
python3 tools/gif-build.py /tmp/gif-lauf/gesamt \
  ../../Ai_Radio_Moderator_Bot/APPENDIX/images/bot-lauf-gesamt-web.gif \
  --abschnitte "6,6:15,6" --zeitgleich --luecke-max 250 --breite 800 --farben 48 \
  --inhalt --inhalt-rand 2 \
  --titel "Radio agent · test run — the whole workflow"
```

For the camera panning, use the same with `--follow 12 --window 1300x740 --width 800
--colors 40 --title "Radio-Agent · Test run — the view follows the run"`.
Adjustment screws for the bar: `--titel-hoehe`, `--titel-hintergrund` (preset
`f2f4f7`), `--titel-schrift` (preset `333b47`).
